# Cloudflare: шаги владельца (этап 7.5)

Дата: 24.11.2026. Домен уже в Cloudflare: записи `@`, `www`, `api` → 206.189.104.166, все «DNS only» (серое облако).
Сервер к прокси готов (этап 4.2): флаг `TRUST_CLOUDFLARE` одним действием закрывает сервер для всех, кроме
Cloudflare, и включает чтение настоящего адреса и страны посетителя. Диапазоны адресов Cloudflare в
`deploy/caddy/cf-true.caddy` сверены со страницей https://www.cloudflare.com/ips/ 24.11.2026 — совпадают.

Ключи и пароли в чат не присылать: их вписываете вы сами в `deploy/.env` на сервере.

## Часть 1. Turnstile — защита от ботов (можно сейчас, ~10 минут)

Посетители этого не заметят: окно проверки появляется только у того, кто делает много раскладов подряд или больше
20 в сутки с одного адреса. Пока ключей нет, такая проверка не может пройти.

1. https://dash.cloudflare.com → в меню слева **Turnstile** → **Add widget**.
2. Widget name: `Arcana Diary`. Hostname: `arcanadiary.com` (поддомены входят сами). Widget mode: **Managed**.
   Pre-clearance: **No**. Нажать **Create**.
3. Cloudflare покажет **Site Key** и **Secret Key**.
4. На сервере в терминале: `nano ~/arcana-diary/deploy/.env`. Добавить две строки (или заменить, если они есть):
   ```
   TURNSTILE_SITEKEY=<Site Key>
   TURNSTILE_SECRET=<Secret Key>
   ```
   Сохранить: Ctrl+O, Enter, Ctrl+X.
5. Написать Claude «ключи вписал». Claude выкладывает и проверяет, что сервер видит оба ключа (только «есть / нет»,
   без значений).

## Часть 2. Прокси — оранжевое облако (одним заходом, ~15 минут, до 10.12)

Между шагами 6 и 7 все посетители приходят с адресов Cloudflare и делят один счётчик раскладов — не растягивать.
Делать, когда Claude на связи: после шага 7 он сразу выкладывает и проверяет.

1. **SSL/TLS → Overview:** режим **Full (strict)**. У сервера настоящий сертификат Let's Encrypt.
2. **SSL/TLS → Edge Certificates → Always Use HTTPS:** **Off**. Сервер сам перенаправляет на HTTPS, а эта настройка
   может сломать продление сертификата (проверка Let's Encrypt идёт по http).
3. **Speed → Optimization → Rocket Loader:** **Off** (переписывает скрипты страницы и может сломать окно расклада).
4. **Security → Bots → Bot Fight Mode:** **Off**. Он может показывать проверку на запросы расклада; защита от ботов у
   нас — Turnstile из части 1 и лимиты сервера.
5. **Боты ИИ и robots.txt** (раздел AI Crawl Control или Security → Bots, название меняется):
   - **Managed robots.txt — Off**: Cloudflare не должен дописывать свой текст в наш `robots.txt` (после запуска его
     проверяет чек-лист).
   - **Блокировка ИИ-ботов** (Block AI bots / AI Crawl Control) — **решение владельца**. Рекомендация: не блокировать,
     чтобы сайт мог попадать в ответы ChatGPT, Perplexity и других ИИ-поисков. До 14.12 сайт закрыт паролем, так что
     сейчас это ни на что не влияет.
6. **DNS → Records:** у `arcanadiary.com`, `www`, `api` нажать на серое облако → станет оранжевым (**Proxied**).
   Записи **AAAA** не добавлять.
7. Сразу после этого: `nano ~/arcana-diary/deploy/.env`, строку `TRUST_CLOUDFLARE=false` заменить на
   `TRUST_CLOUDFLARE=true` (если строки нет — добавить). Сохранить и написать Claude «прокси включил».

Что делает Claude после шага 7: `deploy/deploy.sh`, затем проверки:
- прямой заход на адрес сервера мимо Cloudflare обрывается без ответа;
- через Cloudflare сайт отвечает `401` (стенд под паролем), с паролем — `200`;
- адрес посетителя в журнале API — настоящий, а не адрес Cloudflare;
- расклад на стенде проходит (это проверяете вы в браузере).

## Откат (если что-то сломалось)

1. DNS → у трёх записей оранжевое облако → серое.
2. `nano ~/arcana-diary/deploy/.env`: `TRUST_CLOUDFLARE=false`.
3. Написать Claude «откат» — он выкладывает. Сайт работает как сейчас, без Cloudflare.

## Через сутки после включения

Claude проверяет журнал Caddy на продление сертификата (`docker compose logs caddy | grep -iE 'obtain|renew|error'`).
Если продление когда-нибудь не пройдёт — на время продления откат по шагам выше, затем снова часть 2.
