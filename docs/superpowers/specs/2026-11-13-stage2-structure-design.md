## 1. Адреса и структурный дом

### Правила адреса

- Строчная латиница, слова через дефис. В испанских адресах без диакритики, `ñ` → `n`: `si-o-no`,
  `el-ermitano`.
- Без слеша на конце, в том числе главная ES: основной адрес `/es`. Вариант со слешем или с заглавными
  буквами — 301 на основной. Исключение одно: корень сайта `/`.
- Разделы страницы открываются якорем (`#reversed`, `#love`, `#advice`; ES — `#invertida`, `#amor`,
  `#si-o-no`, `#consejo` — после данных, ES-096, V1.1), отдельных адресов у них нет.
- Сегмент пути без своей страницы (`/horoscope`, `/quiz`, `/es/tiradas` до V1.1) отдаёт 404 и нигде не
  ссылается.
- Служебные слаги внутри `/cards` (`major-arcana`, `combinations`) не совпадают ни с одним `slug_en` карт;
  внутри `/es/cartas` — `arcanos-mayores` не совпадает ни с одним `slug_es`. Проверяет валидатор.
- Редиректов со старых адресов нет: сайт новый, схема плана с `/en/` нигде не публиковалась.

### Испанские названия карт

Правило: одна система имён на колоду. Для старших арканов имя выбирается по спросу MX на базовый запрос
«<имя> tarot»; для придворных рангов и масти — по сумме спроса четырёх мастей, чтобы на хабе не стояли рядом
«Caballo de Bastos» и «Caballero de Copas». Другие варианты имени называются в тексте страницы (этап 5).

## 2. Меню, хлебные крошки, перелинковка

### Меню

Пять пунктов, одинаковых на всех страницах: EN — Reading · Yes or No · Love · Card of the Day · Card Meanings;
ES — Tirada · Sí o no · Amor · Carta del día · Significados. Подсвечен пункт из колонки `menu_item`.

### Хлебные крошки

- Только на справочных страницах: карта, старшие арканы, справочник «да/нет», `3 cartas`, страницы V1.1 с
  домом не на главной. На страницах-инструментах крошек нет: место показывает пункт меню, экран над картами
  свободен (UX).
- Одна основная цепочка на страницу — из колонки `breadcrumb`. Альтернативные входы (из расклада, из
  справочника «да/нет») цепочку не меняют (8.5).
- Звено крошек — только существующая страница со статусом 200.
- У страниц V1.1 на этапе 2 заданы только адрес, дом и пункт меню (если страница в меню); их крошки
  задаются при проектировании волны V1.1.

### Правило ссылки

У каждой связи записаны: момент, когда возникает следующий вопрос; тип связи; действие после перехода;
шаблон анкора. Если действие не формулируется — ссылки нет (8.6). Норма «2–3 термина целевой страницы в
200–350 знаках вокруг ссылки» — проверка текста на этапе 5, а не повод вставлять термины (книга прямо называет
это ошибкой, 8.6).

Типы связи: `подробность`, `метод`, `действие`, `навигация`, `сохранение`.

### Запреты

- Внутри ответа чтения — только ссылки на значения карт и метод. Предложение Plus — отдельным спокойным блоком
  **после** ответа, в дневнике, при исчерпании бесплатного лимита и на странице тарифов. Текст говорит, что
  даёт Plus (память чтеца, длинные расклады, история), и не обещает узнать мысли другого человека. Основания:
  запрет З4 (чтение третьих лиц), З5 (давление страхом), принцип плана «без рекламы в чтении и дневнике»,
  антипример конкурентов (`30-opportunities.md`, раздел 2а).

- Ссылка на страницу V1.1 появляется только в день публикации цели. Валидатор: волна ссылки не раньше волны

- После публикации матрица сверяется с настоящими ссылками в HTML краулером: план не доказывает наличие
  ссылки (8.6).

### Путь пользователя (проверка UX)

С любой страницы запуска до первого расклада — не больше двух действий без регистрации (принцип плана
продукта). Инструменты: расклад начинается на самой странице. Справочные страницы (карта, старшие арканы,
хаб, справочник «да/нет»): одна кнопка-действие ведёт в инструмент. Таблица «страница → число действий до
результата» входит в `docs/research/stage2/00-structure.md`; по шагам пути прорабатываются на этапе 3.

## 3. hreflang

- Пары задаёт таблица `hreflang.csv` по идентификатору сущности, не заменой префикса (2.10). Колонки:
  `entity_id`, `template`, `lang`, `page_id`, `url`, `wave`, `status` (`planned` / `published`),
  `in_hreflang` (`yes` / `no`), `switch_to`.
- `entity_id`: `page:home`, `tool:one-card`, `tool:daily`, `tool:yes-no`, `ref:yes-no-cards`, `tool:love`,
  `hub:cards`, `hub:major-arcana`, `card:<card_id>` (из `cards.csv`), `spread:index`, `spread:celtic-cross`,
  `spread:three-card`, `spread:guidance`, `spread:love`, `tool:birth-card`, `horoscope:<знак>`,
  `ref:zodiac-cards`, `card-yes-no:<card_id>`, `card-feelings:<card_id>`.
- Пару получают только страницы с эквивалентом один к одному.

### Кластеры запуска — 84

Главная, карта дня, да/нет, любовь, хаб, старшие арканы, 78 карт. Сверка с итогом этапа 1: EN 86 страниц =
84 + `/one-card` + `/yes-no/cards`; ES 85 = 84 + `/es/tiradas/3-cartas`.

Без пары и без hreflang: EN `/one-card` (в ES режим одной карты — на главной), `/yes-no/cards` (в ES метод —
строка на странице карты); ES `/es/tiradas/3-cartas` до V1.1.

V1.1: пары `spread:index`, `spread:celtic-cross`, `spread:three-card` (сюда входит `/es/tiradas/3-cartas`),
`tool:birth-card`. Только EN: `spread:guidance`, `spread:love`, гороскопы ×12, `ref:zodiac-cards`,
`card-yes-no` ×78, `card-feelings` ×78.

### Разметка

- `<link rel="alternate">` в `<head>`; на каждой странице кластера — `en`, `es`, `x-default`, включая ссылку на
  себя. `x-default` — английская страница этой же пары.
- Один способ — HTML; в sitemap ссылок на языковые версии нет (смешение способов — ошибка, 2.10).
- canonical каждой версии — на себя; адреса в тегах — основные (без слеша, 200, без параметров).
- Страница входит в кластер в день открытия для индексации; до этого `in_hreflang = no`. На закрытом стенде
  теги собираются и проверяются, но кластер считается действующим с открытия 14.12.2026.
- Перенаправлений по IP и языку браузера нет.

### Переключатель языка

EN | ES в шапке. Страница с парой → пара. Без пары → `switch_to`: `/one-card` → `/es`, `/yes-no/cards` →
`/es/si-o-no`, `/es/tiradas/3-cartas` → `/` (до V1.1). Автоматической плашки нет (план запрещает
всплывающее); тонкая строка под шапкой — после данных о том, что испаноязычные массово попадают на EN.

### Проверка кластера

Восемь пунктов книги (2.10, стр. 145) по каждому кластеру: 200, self-canonical, ссылка на себя, взаимность,
коды, без параметров, без noindex, x-default. Скриптом по `hreflang.csv` — на этапе 2; краулером по стенду — на
этапе 7.

## 4. Техника

- **Не индексируются:** дневник, аккаунт, оплата — за входом, `noindex`, не в sitemap. Поделённое чтение
  `/r/<id>` — `noindex, follow`. В robots.txt эти адреса не закрываются, иначе noindex не будет виден.
- Вопрос и выпавшие карты в адрес не пишутся: это состояние инструмента.
- **Sitemap:** индекс + `sitemap-en.xml` и `sitemap-es.xml`; только 200, индексируемые, self-canonical;
  `lastmod` — дата реальной правки текста. Страницы V1.1 — в день публикации. Наборы ×78 (`yes-or-no`,

### Колонки карты

- `url` — адрес страницы; у строк-шаблонов — шаблон `/cards/{slug_en}/yes-or-no`; у разделов — адрес хозяина
  с якорем; у строк `отклонить`, `получить данные`, `имеющийся ответ` — пусто.
- `entity_id` — по разделу 3; у разделов и пустых строк — пусто.
- `parent_id` — ID дома; у строк ×78 «карта × контекст» — `@same-card`; у главной и разделов — пусто.
- `breadcrumb` — основная цепочка или пусто.
- `menu_item` — `reading`, `yes-no`, `love`, `daily`, `cards` или пусто.
- `host_id` — у разделов ID страницы-хозяина (у разделов на 78 картах — `@cards`); иначе пусто.
- `pages` — число страниц строки: 1, 78, 12 и т. п.; у разделов — 0.

### Колонки матрицы ссылок

`link_id`, `from_id`, `to_id`, `link_type`, `moment`, `anchor_pattern`, `context_terms`, `wave`, `note`.
Токены: `@cards` (все 78 карт языка), `@major` (22 старших), `@minor` (56 младших), `@drawn` (карты, выпавшие
в результате; динамическая связь), `@same-card` (страница той же карты), `@neighbors` (предыдущая и следующая
по колоде), `@diary` (дневник, служебная страница за входом). Связи «×78» записываются одной строкой с токеном.

### Валидатор

`validate_page_map.py`: `kd` — число или `нет данных`; `data_date` — ISO; язык только `en`/`es`, иначе ошибка;
запуск без аргументов — подсказка использования; новые колонки обязательны для v1.3.

`validate_structure.py` (новый): адреса уникальны и по правилам раздела 1; служебные слаги не совпадают со
слагами карт; `parent_id` и `host_id` ссылаются на существующие строки-страницы; цепочка крошек не содержит
страниц позже волны строки; матрица ссылается на существующие строки, волна ссылки не раньше волны цели;
hreflang — пары только один к одному, ровно по одной строке на язык в кластере, `in_hreflang = yes` только у
`published`; на запуск — 84 кластера.

## 7. Ворота перед этапом 4 (код сайта)

Этапы 2 и 3 дают документы; код сайта начинается на этапе 4. До первой строки кода — независимая проверка
итогов этапов 1–3 агентом **Fable 5.2** (`claude-fable-5-2`). Агент получает сами файлы (карты, TGA, адреса,
матрицу ссылок, hreflang, дизайн-систему, прототипы, план продукта) без выводов исполнителя. Он ищет

пользователя. Найденное разбирается с владельцем до начала этапа 4. Записано в `docs/stages.md`.
