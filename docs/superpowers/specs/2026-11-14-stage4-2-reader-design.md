# Этап 4.2: расклад и ИИ-чтец — дизайн

Дата: 14.11.2026. Статус: разделы 1–5 утверждены владельцем в чате 14.11.2026; раздел 8 — решения после проверки Fable 5.2.
Часть этапа 4 «Ядро продукта» (4.1 база карт → **4.2 расклад и чтец** → 4.3 аккаунт и дневник → 4.4 интерфейс
ядра). Основания: план продукта (раздел «Как устроен ИИ-чтец», «Техника и стек», «Этика чтения»), решения
владельца перед этапом 4 (`docs/design/00-design.md`, таблица 1–9), отчёт ворот перед этапом 4 (Б1, Б3, С2–С5,
С13), база карт 4.1 (`content/cards/`), запреты З1–З6 (`docs/research/stage1/10-task-map.md`).

## Цель

API, через который гость получает полный расклад без аккаунта: карты, вердикт «да/нет», толкование чтеца на
нашей базе значений потоком, два уточнения, карту дня; с лимитом «3 в день», защитой от ботов, отказом по
запретным темам и кризисным ответом. После 4.2 весь путь гостя проверяется через API; экраны — 4.4.

| Вопрос | Решение |

## 1. Поток расклада

### 1.1. Адреса API

Сайт обращается к API по пути `/api/` на основном домене: Caddy проксирует `arcanadiary.com/api/*` в сервис
`api` (первая сторона — служебная cookie без CORS; для потока — `flush_interval -1`). Поддомен
`api.arcanadiary.com` остаётся для `/health`.

| Метод и путь | Что делает |
|---|---|
| `POST /api/readings` | создать расклад: `lang` (`en`/`es`), `kind` (`one`, `three`, `yes_no`, `card_page`), `question` (необязательно, до 500 знаков), `topic` (необязательно: `love`, `work`, `self`, `decision`, `general`), `situation` (необязательно, ключ ситуации `/love`), `card_id` (только для `card_page` — страница, с которой вытягивают), `tz` (часовой пояс браузера); ответ — номер расклада, карты, вердикт (для `yes_no`), группа проверки вопроса, остаток лимита |
| `GET /api/readings/{id}/stream` | поток толкования (Server-Sent Events); второй запрос на тот же расклад отдаёт сохранённый текст |
| `POST /api/readings/{id}/followups` | уточнение: `question`; ответ — поток; не больше двух на расклад, третье — `402` с признаком «Plus» |
| `GET /api/readings/{id}` | расклад целиком (карты, вердикт, текст, уточнения) — для «Назад», обновления страницы и ссылки |
| `GET /api/daily?lang=&tz=` | карта дня этого посетителя и её текст |
| `GET /api/limits?tz=` | сколько раскладов осталось сегодня |

`kind=card_page` — одна карта, вытянутая со страницы карты (экран 8b): вытягивается из всей колоды, как `one`;
`card_id` пишется только как источник. Все виды, кроме карты дня, входят в лимит.

### 1.2. Порядок при `POST /api/readings`

1. Проверка Turnstile, если её потребовал сервер (раздел 4.2).
2. Лимит «3 в день» (раздел 4.1); исчерпан — `429` с признаком «лимит», сайт показывает экран 11a.
3. Проверка вопроса (раздел 3), если вопрос есть; кризис — ответ без расклада, лимит не тратится.
4. Вытягивание: криптографически случайное зерно (`secrets`), из него — перестановка колоды и ориентации;
   каждая карта перевёрнута с вероятностью 1/2; одна карта — `one`, `yes_no`, `card_page`; три — `three`
   (позиции: прошлое, настоящее, куда ведёт). Зерно сохраняется: по нему расклад воспроизводится тем же.
5. Вердикт для `yes_no` — функция из `tools/cards/yes_no.py` (переносится в пакет API, раздел 6) по
   `content/cards/yes-no-rules.json`.
6. Запись расклада в базу; ответ сайту — сразу, до текста чтеца.

### 1.3. Перевёрнутые карты

Всегда включены (решение 1). Вердикт перевёрнутой карты — `unclear` по правилу 4.1.

## 2. Чтец

### 2.1. Вход модели

- вопрос или пометка «без вопроса»; тема и ситуация, при пустом выборе — «ситуация не указана» (С13);
- карты с позициями и ориентацией;
- выдержки из `content/cards/meanings.<lang>.json` по каждой карте: `keywords`, `upright` или `reversed` по
  ориентации, `love` — для темы `love`, `advice`; для `yes_no` — вердикт, посчитанный кодом, и подпись из
  `yes-no-rules.json`;
- группа проверки вопроса (раздел 3) — для запретной темы указание перевести вопрос на самого человека.

Модель толкует только по выдержкам; значения карт по памяти модели не берутся.

### 2.2. Выход модели

Разделы ответа, в этом порядке, каждый с меткой, по которой сайт раскладывает текст по экрану:

1. `headline` — ответ одной строкой;
2. `cards` — по каждой карте 2–3 предложения, привязанные к вопросу;
3. `synthesis` — 1–2 предложения (для одной карты не пишется);
4. `step` — один конкретный шаг на сегодня или неделю;
5. `why` — только для `yes_no`: строка «почему» под вердиктом, без слов вердикта.

Объём: три карты — 180–250 слов, одна карта — 90–150 слов. Метки разделов — простые строки-разделители в
потоке; разбор — на сервере, сайт получает события `section` и `text`.

### 2.3. Уточнения

Модель получает расклад, первый ответ и новый вопрос; отвечает 60–120 словами по тем же картам, новых не
вытягивает. Вопрос уточнения тоже проходит проверку раздела 3. Два уточнения бесплатно; дальше — карточка Plus
(цена и запись в список ожидания — решение 6).

### 2.4. Голос и промпты

Один персонаж — спокойный старший друг. Вероятностный язык («может говорить о…»), без «будет», без
медицинских, юридических и денежных указаний, без мыслей и чувств другого человека, без запугивания (З1–З6).
Промпты — отдельные файлы на английском и мексиканском испанском (на «tú»), не перевод; лежат в репозитории
(`api/app/reader/prompts/`), у каждого — номер версии; версия пишется в расклад.

### 2.5. Проверка ответа

После потока сервер проверяет текст словарём `tools/cards/banned_terms.json` (тот же, что для базы) и длиной:

- `why` со словом вердикта или запрещённым словом → общая строка на язык:
  EN «The card is reversed, so its answer softens: not clear yet.» (для прямой карты — `yes_no_why` из базы),
  ES «La carta salió invertida: su respuesta se suaviza, todavía no está claro.»;
- запрещённое слово в остальном тексте → ответ заменяется значениями карт из базы со строкой «чтец сейчас
  недоступен» (раздел 5); сохраняются оба текста, показывается замена.

Поток уже показан человеку к моменту проверки: при замене сайт получает событие `replace` и перерисовывает
ответ. Проверка ловит редкие сбои; основная защита — промпт и проверка вопроса.

### 2.6. Карта дня

Карта: зерно = хэш (номер гостя, дата по его часовому поясу) — одна и та же весь день, новая после полуночи.
Текст: один на (карта, ориентация, язык, дата UTC), пишется при первом запросе и хранится в кэше; короткий,
60–100 слов: смысл на сегодня и один шаг. Повторные запросы и другие посетители с той же картой получают
кэш. В лимит не входит.

### 2.7. Поставщик и модель

Модуль поставщика (`api/app/reader/provider.py`): вход — системный промпт, сообщения, предел токенов;
выход — поток текстовых кусков и итог (токены, причина остановки). Первая реализация — Claude через
официальный SDK `anthropic`, потоковый вызов. Модель — `READER_MODEL` (по умолчанию `claude-haiku-5-5`),
модель проверки вопроса — `GUARD_MODEL` (тоже `claude-haiku-5-5`). Отказ модели (`stop_reason: refusal`) —
как ошибка (раздел 5). Gemini и GPT — отдельные реализации того же модуля, позже.

## 3. Безопасность вопроса

### 3.1. Проверка до расклада

Короткий отдельный вызов `GUARD_MODEL` со структурированным ответом относит вопрос к группе:

| Группа | Что происходит |
|---|---|
| `ok` | обычный расклад |
| `redirect_topic` — здоровье, беременность, смерть, суды, деньги и сделки как прогноз | расклад; чтец переводит вопрос на самого человека; над ответом мягкая строка «о таком карты не предсказывают» |
| `redirect_person` — чужие мысли, чувства, слежка («что он думает», «изменяет ли») | расклад о самом человеке и его выборе |
| `crisis` — мысли о самоубийстве, вреде себе, насилие | расклада нет; тёплый ответ и контакты помощи; лимит не тратится |

До вызова модели — фильтр стоп-слов на двух языках (`api/app/safety/crisis_terms.json`): совпадение сразу даёт
`crisis`. При сбое или тайм-ауте модели проверки (3 секунды) — группа по фильтру, иначе `ok`; ответ чтеца всё
равно проходит раздел 2.5.

### 3.2. Кризисный ответ и контакты

Контакты — `api/app/safety/helplines.json`: страна (ISO), название, номер, звонок/SMS, часы, язык, источник,
дата проверки. Страна — заголовок `CF-IPCountry`, только для этого ответа, не сохраняется. На запуске:

| Страна | Контакт | Статус |
|---|---|---|
| США | 988 Suicide & Crisis Lifeline — звонок или SMS 988 | проверено 14.11.2026 |
| Мексика | Línea de la Vida — 800 911 2000, круглосуточно, CONASAMA | проверено 14.11.2026 |
| Испания | Línea 024, Министерство здравоохранения; угроза жизни — 112 | проверено 14.11.2026 |
| Аргентина | 135 (Буэнос-Айрес и пригороды), (011) 5275-1135 — вся страна | проверено 14.11.2026 |
| Колумбия | Línea 106 | **проверить перед запуском** (вариант «192, опция 4» найден только у страховщика) |
| остальные | findahelpline.com + местный номер экстренной службы | — |

### 3.3. Тексты

Кризисный ответ, мягкая строка для запретной темы и строка о передаче вопроса поставщику модели (рядом с полем
вопроса, со ссылкой на политику — решение 8) — черновики Claude на двух языках в
`api/app/safety/texts.<lang>.json`, статус `draft`; владелец проверяет до запуска.

### 3.4. Что не хранится

При `crisis` текст вопроса не сохраняется — только отметка «кризисный ответ показан» и язык. Группа проверки
хранится у расклада без отдельной копии вопроса.

## 4. Лимиты, защита, хранение

### 4.1. Лимит «3 в день»

- Входят: `one`, `three`, `yes_no`, `card_page`. Не входят: карта дня, уточнения, кризисный ответ, повтор
  после сбоя чтеца (раздел 5).
- Гость — служебная cookie `ad_guest` (случайный номер, HttpOnly, Secure, SameSite=Lax, 1 год); окна согласия
  не требует. Вошедший (4.3) — тот же счётчик по аккаунту.
- День — по часовому поясу из браузера (`tz`, имя IANA); сервер принимает только существующие пояса, иначе UTC.
  Сброс — в полночь этого пояса.

### 4.2. Защита от ботов

- Запасной счётчик по адресу: хэш (IP + соль суток); соль меняется раз в сутки и не хранится дольше суток.
  Порог — 20 раскладов в сутки с адреса и всплеск — 5 запросов `POST /api/readings` за минуту.
- После порога сервер отвечает `403` с признаком «нужна проверка»; сайт грузит скрипт Turnstile (только в этот
  момент), получает токен невидимо и повторяет запрос с ним. Сервер проверяет токен у Cloudflare.

### 4.3. База (Supabase Postgres)

| Таблица | Поля |
|---|---|
| `readings` | `id` (UUID v4), `guest_id`, `user_id` (пусто до 4.3), `lang`, `kind`, `question`, `topic`, `situation`, `source_card_id`, `cards` (JSON: card_id, позиция, перевёрнута), `seed`, `verdict`, `guard_group`, `answer` (JSON по разделам), `answer_shown` (`model` / `fallback`), `model`, `prompt_version`, `created_at`, `expires_at` |
| `followups` | `id`, `reading_id`, `n` (1–2), `question`, `answer`, `model`, `created_at` |
| `daily_cache` | `card_id`, `reversed`, `lang`, `day`, `text`, `model`, `prompt_version` — уникальна по первым четырём |
| `daily_draws` | `guest_id`, `day`, `card_id`, `reversed` |
| `usage` | `guest_id`, `day`, `count`; `ip_hash`, `day`, `count` |
| `guard_events` | `day`, `lang`, `group` — счёт без текста |
| `llm_calls` | `reading_id`, `purpose` (`reader`, `followup`, `daily`, `guard`), `model`, `ms_first_token`, `ms_total`, `tokens_in`, `tokens_out`, `cost_usd`, `stop_reason` — без текстов |

- Доступ — только из API по серверному ключу; в базе включены правила доступа (RLS) без открытых политик, так
  что прямой доступ из браузера закрыт.
- Схема — SQL-миграции в репозитории (`api/migrations/`).
- `expires_at` гостевого расклада — +7 дней; раз в сутки API удаляет просроченные расклады с уточнениями
  (задача при старте и по таймеру внутри процесса, без отдельной очереди). Привязка к аккаунту — 4.3.

## 5. Ошибки, качество, журнал

### 5.1. Ошибки

| Что случилось | Ответ |
|---|---|
| нет первых слов за 15 секунд, ошибка API, отказ модели | событие `fallback`: значения выпавших карт из базы + строка «чтец сейчас недоступен» + кнопка «попробовать ещё раз»; повтор — `POST /api/readings/{id}/retry`, лимит не тратит, не больше двух повторов |
| поток оборвался | написанное остаётся; недописанные карты — значениями из базы |
| нарушение в тексте | раздел 2.5 |
| нет сети у человека | `GET /api/readings/{id}` восстанавливает расклад |
| база недоступна | `503`; расклад не создаётся, лимит не тратится |

### 5.2. Тесты

Детерминированный код — полностью, с заглушкой поставщика (бесплатно): вытягивание по зерну, вердикт, лимиты и
сброс в полночь разных поясов, счётчик по адресу, группы проверки и фильтр стоп-слов, раздел 2.5, запасные
ответы, разбор разделов потока, кэш карты дня, сроки хранения. База в тестах — Postgres в Docker.

### 5.3. Тестовый набор чтеца

`api/evals/` — 50 вопросов на язык: любовь, работа, решение, «да/нет», без вопроса, ситуации `/love`, запретные
темы, кризис, попытки «что он думает». Оценка — отдельная модель-судья по четырём критериям плана (по делу,
конкретно, тепло, безопасно; 1–5) и автоматические проверки (словарь запретов, длина, разделы, отсутствие слов
вердикта в `why`). Каждый прогон стоит денег — запускается только с «да» владельца, с названной заранее ценой.
Порог для потока: средняя ≥ 4 по каждому критерию на каждом языке и ни одного нарушения безопасности.

### 5.4. Журнал

Таблица `llm_calls` (раздел 4.3) и строка лога на каждый вызов: модель, версия промпта, время до первых слов,
длительность, токены, стоимость. Тексты вопросов в журнал не пишутся.

## 6. Код

```
api/app/
  main.py               — приложение, подключение маршрутов
  config.py             — переменные окружения
  cards.py              — загрузка content/cards/*.json, вердикт (перенос yes_no.py), выдержки
  draw.py               — зерно, перестановка, ориентация, карта дня
  routes/               — readings.py, daily.py, limits.py
  reader/               — provider.py, claude.py, prompts/, compose.py (вход модели), sections.py (разбор
                          потока), check.py (раздел 2.5), fallback.py
  safety/               — guard.py, crisis_terms.json, helplines.json, texts.en.json, texts.es.json
  limits.py, turnstile.py, db.py
api/migrations/         — SQL
api/evals/              — вопросы, судья, запуск
api/tests/
```

`tools/cards/yes_no.py` остаётся эталоном для базы; API импортирует общее правило из одного места (функции
переносятся в `api/app/cards.py`, `tools/cards/yes_no.py` вызывает их или тест сверяет обе реализации на всех
сочетаниях). Новые зависимости: `anthropic`, `psycopg[binary]`, `httpx` (уже есть для тестов).

## 7. Что нужно от владельца

1. Ключ Claude API (Anthropic Console) и пополнение баланса — достаточно $10.
2. Проект Supabase, бесплатный тариф, регион ЕС (Франкфурт).
3. Cloudflare Turnstile: виджет в панели Cloudflare, два ключа.
4. Проверка текстов раздела 3.3, контактов (Колумбия) и первого прогона тестового набора.

Ключи — только в `deploy/.env` на сервере; в репозиторий не попадают. До ключей всё пишется и проверяется на
заглушках и локальном Postgres.

## 8. Решения после проверки Fable 5.2 (14.11.2026)

Независимая проверка спецификации и плана (Fable 5.2, «готово после исправлений») — отчёт в рабочей папке
`.superpowers/sdd/s42-fable-review.md`. Решения владельца в чате 14.11.2026; где раздел ниже расходится с
разделами 1–7, верен он.

1. **Вердикт «да/нет» на запретную тему — по темам.** Здоровье, беременность, смерть, суды, безопасность
   (`redirect_topic`, кроме денег) и чужие мысли (`redirect_person`): вердикта и `why` нет — расклад на одну
   карту о самом человеке и мягкая строка «о таком карты не предсказывают». Деньги, покупки, вложения: вердикт
   показывается с дисклеймером «это не финансовый совет» (EN «This isn't financial advice.», ES «Esto no es un
   consejo financiero.»); `why` — о готовности и настрое человека, не о рынке; `step` — всегда трезвый (проверить
   цифры, обсудить с тем, кто разбирается в финансах). Проверка вопроса различает `redirect_money` и
   `redirect_topic`.
2. **Cloudflare.** Прокси Cloudflare включается до запуска; сервер принимает запросы только с адресов Cloudflare.
   Пока прокси нет (настройка `TRUST_CLOUDFLARE=false`), заголовки `CF-Connecting-IP` и `CF-IPCountry` не
   читаются: адрес — из соединения, телефоны помощи — по часовому поясу и языку.
3. **Ссылка на расклад** показывает только карты и ответ; вопрос, тема и уточнения — только автору (cookie
   `ad_guest`). Первый поток толкования запускает только автор.
4. **Потолок расходов.** Жёсткий предел — 60 раскладов в сутки с одного адреса (сверх — отказ, Turnstile не
   помогает); бюджет модели — $5 в сутки по таблице `llm_calls` (настройка `DAILY_BUDGET_USD`); сверх
   бюджета — значения карт из базы и строка «чтец сейчас недоступен».
5. **Ситуации `/love`** — четыре утверждённые на этапе 3: `single`, `relationship`, `after_breakup`,
   `complicated` (Single, In a relationship, After a breakup, It's complicated).
6. **Сбой проверки вопроса.** Отказ модели проверки → кризисный ответ; тайм-аут → `ok`, как в разделе 3.1, но
   в промпте чтеца — своя страховка (признаки кризиса → короткий тёплый ответ и строка о помощи вместо
   толкования); тайм-ауты и отказы считаются в `guard_events`. Стоп-фразы нормализуются (регистр, ударения,
   апострофы) и расширяются; ложные срабатывания проверяются тестами.
7. **Насилие.** Добавляются линии: США — National Domestic Violence Hotline, 1-800-799-7233, SMS START на
   88788, круглосуточно (thehotline.org, проверено 14.11.2026); Мексика — Línea de las Mujeres, 079, опция 1,
   круглосуточно, Secretaría de las Mujeres (проверено 14.11.2026 по прессе; до запуска сверить с gob.mx).
8. **Карта дня** — все 312 текстов (78 карт × 2 ориентации × 2 языка) пишутся заранее раз в сутки, около
   $0,10 в день; запрос карты дня не ждёт модель; при сбое — значения из базы.
9. **Тестовый набор** — плюс около 60 вопросов только для проверки вопроса (кризис и похожие безобидные
   фразы, EN и ES) и 10 попыток взлома чтеца; в прогоне пишутся источник группы (стоп-фраза, модель, сбой) и
   время проверки; судья проверяется на заведомо плохих ответах.
10. **Проверка ответа (раздел 2.5)** не выбрасывает ответ за упоминание темы («pregnancy», «embarazo»): для
    живого ответа — отдельный словарь утверждений-предсказаний, а не словарь базы; в `why` запрещены слова
    вердикта как ответ («yes», «sí», «the answer is no»), но не любое «no» («no hay prisa»).
11. **Прочее из проверки:** поддомен `api.` отдаёт только `/health`; лимит «3 в день» считается атомарно в той
    же транзакции, что и создание расклада; обрыв соединения не теряет ответ (генерация дописывается и
    сохраняется) и не сжигает уточнение.

## 9. Решения после повторной проверки Fable 5.2 (17.11.2026)

Владелец ответил на девять вопросов повторной проверки плана. Раздел дополняет 1–8 и при расхождении
главнее их.

1. **Лотерея и ставки** («выиграю ли я в лотерею», «поставить ли на матч», «купить ли билет») — группа
   `redirect_money`: вердикт «да/нет» с оговоркой «This isn't financial advice.» / «Esto no es un consejo
   financiero.», «почему» — о готовности, шаг — трезвый. Не `redirect_topic`.
2. **Расходы на уточнения и проверку вопроса** — три ограничения: не больше 4 попыток уточнения на расклад
   (считая кризисные ответы, отказы и сбои); дневной лимит уточнений с одного адреса; отдельный денежный
   потолок на проверку вопроса моделью. Выше потолка проверки — ответ «сервис временно недоступен», а не
   ответ без проверки. Проверка вопроса при исчерпанном общем бюджете `DAILY_BUDGET_USD` продолжает работать до
   своего потолка.
3. **Стоп-фразы.** Однозначные (самоубийство, самоповреждение, «муж меня бьёт») — кризисный ответ сразу, без
   модели. Двусмысленные («hurt myself if I go back to my ex», «lastimarme otra vez») сначала решает модель;
   если модель не ответила, отказала или ответ не разобран — кризисный ответ.
4. **Сбой уточнения** (обрыв, замена запасным текстом, замена по словарю) не тратит одно из двух бесплатных
   уточнений; оба текста сохраняются. Защита от злоупотребления — ограничение из пункта 2.
5. **Расклад, закрытый кризисной меткой чтеца, списывается** из дневного лимита «3 в день» (без возврата).
6. **Строка-оговорка над ответом показывается и по ссылке «поделиться»** (вопрос, тема, ситуация и уточнения
   по-прежнему только владельцу).
7. **Хранение журналов:** `llm_calls` — 90 дней, `guard_events` (анонимные дневные счётчики) — 365 дней.
8. **Карта дня — по местной дате посетителя**; готовые тексты держатся на три дня (вчера, сегодня, завтра):
   первый запуск — 936 текстов, дальше 312 в день.
9. **Тестовый набор** дополняется выборкой уточнений и текстов карты дня на обоих языках (≈ +$0.30, итого
   ≈ $2.02); платный прогон — только после «да» владельца.

Остальные замечания повторной проверки (К3, В13–В16 и дешёвые мелкие) исправляются в плане без отдельного
решения владельца; список — `.superpowers/sdd/s42-fable-rereview.md`.

## 10. Решения после финальной проверки Fable 5.2 (17.11.2026)

Дополняет разделы 1–9 и при расхождении главнее их.

1. **Уточнения: 2 бесплатно к каждому раскладу, дальше — из дневного лимита.** Третье и следующие уточнения
   списывают по одному раскладу из «3 в день» (атомарно, тем же счётчиком). Клиент должен явно подтвердить
   списание (экран 4.4 предупреждает «это потратит 1 расклад»); без подтверждения API отвечает `402` с числом
   оставшихся раскладов. Лимит исчерпан — `402` Plus. Заменяет «третье уточнение — сразу Plus» из разделов 2 и 8.
   Сбой платного уточнения возвращает расклад в лимит (как §9.4); кризис по проверке вопроса расклад не
   списывает; кризисная метка чтеца — списывает (как §9.5).
2. **Предохранитель попыток** на расклад поднимается с 4 до 8 (считая кризисные ответы, отказы и сбои):
   при новой модели успешных уточнений может быть до четырёх.
3. **Предохранители от ботов приняты:** 40 уточнений с адреса в сутки, `GUARD_BUDGET_USD` = 1, Turnstile только
   на создание расклада, на уточнения не ставится. Числа — настройки, пересмотр после первой недели.
4. **Оценка платного прогона набора** — ≈ $2.21 (принято владельцем); запуск — только после отдельного «да».
5. Замечания финальной проверки В17 (немедленные стоп-фразы срабатывают на вопросы об отношениях) и В18
   (кризисный ответ при создании расклада не считается по адресу и идёт до Turnstile) исправляются в плане;
   список — `.superpowers/sdd/s42-fable-final.md`.
